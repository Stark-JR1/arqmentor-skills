# ArqMentor v2 — Working Agreement

## Objetivo
Reduzir retrabalho em tarefas técnicas recorrentes por meio de roteamento, preservação, validação e entrega verificável.

## Ordem padrão
`AIZEN -> Skill(s) de domínio -> ITACHI`

## Regras permanentes
- Inspecionar antes de editar.
- Corrigir causa raiz, não apenas sintoma.
- Preservar comportamento existente fora do escopo solicitado.
- Não assumir regra de negócio quando houver mais de uma explicação plausível.
- Não confundir arquivo salvo com arquivo validado.
- Não repetir uma ferramenta com falha de transporte/sessão mais de uma vez sem mudar a estratégia.
- Manter original intacto por padrão e gerar versão nova.
- Toda entrega deve ter evidência mínima de validação.

## Ambiente preferencial
- Windows 11
- Microsoft 365
- Python 3.12
- PowerShell
- VS Code
- Git/GitHub
- Power BI

## Prioridade de domínios
1. Excel
2. Power BI
3. Python/automação
4. SQL/dados
5. Codex/VS Code
6. GitHub
7. Documento/PDF/OCR
8. Financeiro/estoque/processos administrativos

## Critério de pergunta
Perguntar antes quando a decisão puder alterar:
- regra de negócio;
- valores/dados;
- arquitetura;
- produção/remoto;
- exclusão/sobrescrita;
- interpretação documental crítica;
- resultado final de forma material.

Não perguntar por detalhe reversível que possa ser validado depois.
